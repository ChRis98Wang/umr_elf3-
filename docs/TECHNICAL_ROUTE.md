# ELF3 UMR 技术路线

这里发布的是离线参考动作生成与审查工具，不是行为策略训练器。

```text
合法持有的 AMASS SMPL-X + 人体模型          固定 ELF3 URDF/mesh
                   │                               │
        全时钟人体表面准备                  31 关节 MuJoCo 转换
                   └────────────┬──────────────────┘
                         Stage I 对应学习
                                │
                         Stage II 连续 IK
                                │
                        全身 B 样条优化候选
                                │
                       原始与优化结果分开审查
                        ┌───────┴────────┐
                     隔离/待优化       待人工复核
```

最后没有“自动训练”箭头：运动学合格还不是动力学跟踪、负载操作或实机安全合格。

## 1. 数据和坐标系

`umr_smplx_source.py` / `umr_full_source_v5.py` /
`umr_heading_source_v6.py` 从真实 SMPL-X 网格构造表面，不用程序化骨架替代人体。
同一个采样点在整条动作中保留相同三角形与重心坐标，跟随蒙皮表面变形。

时间从源首帧开始，以 50 Hz 采样到源时长内最后一个合法时间点，不拉伸末帧、
不因为长动作就截成短片。首帧朝向由 pelvis 前轴水平投影确定；退化时用人体左轴
和世界竖直轴定义固定参考。分支只在 t0 选一次，不逐帧切换。

冻结 core/v5 的代码 SHA 必须匹配；两个文件在本次独立发布中保持逐字节不变。
[历史朝向协议](UMR_HEADING_RECOVERY_V6_20260912.md)保留的是当时的验证范围，
其中旧目录仅为历史标识，不是新用户需要下载的依赖。

## 2. ELF3 形态契约

`elf3_umr_asset.py` 从固定提交下载机器人资产，将原始 URDF 转成 MuJoCo 模型：

- 全部 31 个活动关节，浮动根位姿 7 维，总 `qpos` 为 38 维，速度空间为 37 维。
- 根刚体为 `torso_link`；稀疏骨盆目标应使用 `waist_z_link`，二者不可混为一谈。
- 保存的是根四元数 `wxyz`，不是 `xyzw`。
- 原始关节轴、范围、连杆变换和惯量保留；脚底约束使用实际 ELF3 脚网格极值点。
- 上游控制参数表有 29 个身体策略关节和 2 个独立头部默认命令；
  这不表示可以从重定向输出中丢弃两个头部关节。

`prepare_elf3_migration.py contract` 只通过 AST 解析上游参数，不执行下载的 Python。
`elf3_joint_contract.py` 独立校验关节、URDF 和参数来源，无需 IsaacLab。

## 3. UMR 的模型在哪里

Stage I 使用固定非官方 UMR 后端学习 canonical 人体表面到机器人表面的对应。
批处理配方使用 4,096 个点、2,500 个学习 epoch。对应结果绑定到机器人连杆局部坐标。

缓存校验真实 canonical 几何、完整形状参数、采样身份、机器人几何、代码版本和配方。
相同文件夹或相同 actor 名称不代表缓存可复用。不能把 G1 对应关系换个文件名当 ELF3 用。

Stage II 使用已学习的对应，在 MuJoCo/Mink 中逐帧求解 IK；整条动作只维护一份连续
求解状态，保留源动作时钟。神经对应学习是模型学习，但输出 `qpos` 不是闭环控制策略。

## 4. 全身优化模型

`WholeBodyObjective` 将根平移、根 SO(3) 旋转参数和 31 个关节统一参数化，使用
三次 B 样条控制点描述轨迹，默认结点间隔 0.12 s。目标综合人体表面保真、脚部保真、
手臂末端位置/姿态、时间平滑和地面/自碰撞距离项。

优化修改模型中的连续轨迹，不是导出时逐帧裁剪速度、冻结问题关节或整体抬高成片。
但当前它仍会不收敛、穿地或发生自碰撞；软代价不能当成约束满足证明。

原始 MuJoCo 碰撞几何检查和 80 对手臂—躯干可见网格凸包筛查分开记录。
距离不可信时不能凭空补一个正间隙；距离上下界校验无法收敛则失败退出。
凸包报警不等于三角网格真实穿透深度，也不是全身无碰撞证明。

## 5. 验收层次与训练边界

1. **完整性**：源/代码/机器人/输出 hash、完整时钟、31 关节布局、IK 失败计数。
2. **运动学门槛**：优化收敛、原始角度与速度限位、脚底不低于 0、碰撞筛查、末端保真。
3. **待复核**：即使上一步通过，结果只进入 `kinematic_review_required`。
4. **后续工作**：人体对应语义复核、支持面/物体场景、物理跟踪验证、训练数据封装，
   然后才讨论 ELF3 ScaleBFM 策略训练与分层评估。本仓库没有自动执行这些环节。

当前工程门槛包括末端位移 P95 ≤ 20 mm、最大值 ≤ 50 mm，人体表面平均误差
相对原始结果的增加 ≤ 5 mm；碰撞深度 ≤ 1e-6 m。它们是当前研究筛选配方，
不是经过实机标定的通用安全标准。

## 6. 接下来应该改什么

优先解决收敛和几何质量，再扩大全库重算：

1. 根旋转支持连续多坐标表示，处理当前绕圈/多圈转身失败。
2. 为长动作设计保持跨窗口连续性、源时钟和边界导数的优化方法。
3. 改进接触目标和优化数值条件，降低穿地与碰撞，不靠放宽验收掩盖问题。
4. 对冻结代表样本做修改前后同源对比，再独立评估完整批次。

这些是后续研发事项，不是本次打包已经解决的功能。
